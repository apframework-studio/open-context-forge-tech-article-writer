# Graphify 任务反馈：本轮升级范围

一次 Graphify 文章从写作到发布暴露出状态、证据边界和交接问题。本轮只升级 Writer 产物的可信度与可交接性；MDX 转换、静态资源复制、构建和上线验证仍由 Article Publisher 负责。

## 本轮实施

1. **任务契约**：记录 `article_mode`、`output_intent`、`edit_scope`、已确认的大纲/标题/验证范围。明确“不修改”“适当修改”和“全文重写”的不同写权限；已确认的决策不重复询问。
2. **状态契约**：`project.md` 记录正文、证据、公开来源、视觉、编辑、渲染状态。每次产物及检查完成后同步；修改正文、引用、图片或模式时按影响回退。`public_readiness_status` 是据此推导的结果，不由 Agent 任意填写。发布状态只接受 Publisher 的结果。
3. **证据契约**：`notes/claim-register.md` 只登记文章关键判断，通过 ID 关联 evidence ledger；分别记录判断类型、证据强度、验证范围与正文处理方式。`notes/verification-log.md` 记录真实命令、时间、版本、退出状态与内部输出位置。未完成的全量验证不能写成完成，受控验证不能外推为全项目 benchmark。
4. **公开来源**：`notes/public-source-map.md` 将内部证据 ID 映射到读者可访问的来源、原文信息和已有博客。公开成稿 `article.md` 不含内部路径。亲身实测可以在安全脱敏后说明方法与范围，不强制虚构公开 URL。
5. **预检**：扩展现有 `check-article.js`，保留原有调用，增加公开意图及项目状态检查；输出 P0/P1/P2/INFO。自动阻断只覆盖可确定的语法、路径、缺失素材和状态冲突；论断归属、benchmark 外推和可读性仍由人审查。
6. **交接**：Writer 生成可审查的交接说明，列出成稿、hash、公开来源、素材、状态与未核实项。Publisher 独立生成渠道产物和发布阶段证据；Writer 不标记构建或上线成功。

## 不在本轮实施

- Writer 内实现 MDX 编译、博客构建、部署或线上访问检查。
- 对“AI 味”、benchmark 真实性、分析判断是否冒充事实给出自动分数或正则式定罪。
- 所有图像强制双格式；现有图示规则在本轮改为按目标渲染器选择交付格式并保留可编辑源文件。
- 无条件先跑全量扫描；只有全量验证失败、过慢或不适用时才缩小范围并记录边界。

## 兼容与验收

- 旧项目没有新字段时不得被直接判为已公开准备好；读取旧内容后补充状态，不覆盖旧稿。
- `internal_note` 不生成面向公开的 `article.md`；新生成的 `article.md` 必须避免内部路径，但“可审阅”不自动等于“公开来源齐备”。
- 只读请求不改正文；若用户禁止任何文件写入，也不更新项目状态。
- 局部修改保留其他章节；全文重写才归档旧稿并重走完整审查。
- 修改正文后旧的渲染和审稿通过状态失效；修改引用后公开来源状态失效；修改图片路径后视觉与渲染状态失效。
- 单次 extract、局部代码检查或未完成扫描在正文和报告中保持原有范围。
- Publisher 的 `prepared`、`written-to-repository`、`built`、`live` 分开报告；只有公开 URL 实际核对后才称上线。
