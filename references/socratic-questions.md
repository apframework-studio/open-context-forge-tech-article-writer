# Socratic Questions

用于写作前澄清会改变文章方向的问题。先按 [文章模式](article-modes.md) 判断任务；只有 `opinion` 必须澄清作者立场，其他模式可以围绕问题、步骤、评估标准或案例事实推进。

## 使用规则

- 一次只问 1-3 个问题。
- 优先问能改变文章方向的问题。
- 不把问题变成访谈清单；当前模式的关键问题足够清楚后停止追问。
- 如果用户已经把当前模式所需信息表达清楚，不重复追问。

## `opinion` 的五个核心问题

1. 你真正想表达的判断是什么？
2. 这个判断反对了什么流行看法？
3. 你有什么亲身经验、工程验证或资料依据？
4. 读者读完后应该改变什么认知或行动？
5. 这篇文章最锋利的一句话是什么？

`analysis` 优先问分析对象、比较维度、证据范围与需要解释的机制；用户明确说“不做观点倾向”时，不问其反对什么或最锋利的立场句。`tutorial` 问读者要完成的任务和验证条件；`review` 问评估标准；`case-study` 问实践过程和可观察结果。

## 按场景追问

### 工具深度解析

- 这个工具解决的真问题是什么，而不是它宣传的功能是什么？
- 它和普通 prompt、workflow、framework 或平台的边界在哪里？
- 它的工程价值来自模型能力，还是来自结构、状态、约束、模板、hook、协议？
- 它适合什么团队，不适合什么团队？
- 它出现说明了什么趋势？

### AI Agent / Workflow

- 这个案例体现的是 Agent 能力提升，还是流程约束增强？
- 哪些环节必须有 human gate？
- 哪些输出必须成为 artifact，而不是对话结果？
- 它和你已有的 skill / workflow / vault 思路有什么相互印证？

### 技术趋势判断

- 你判断这个趋势成立的信号是什么？
- 哪些反例会削弱这个判断？
- 它是短期 hype，还是长期结构变化？
- 这个变化会影响开发者、组织流程还是产品形态？

### 实践复盘

- 你原本以为最难的是什么，实际最难的是什么？
- 哪个步骤最容易被低估？
- 这次实践改变了你对工具、流程或产品的什么判断？
- 读者可以直接复用的最小动作是什么？

## 停止追问条件

`opinion` 满足以下条件即可进入 stance / brief：

- 有一句清晰核心判断。
- 有明确反对对象或误区。
- 支撑依据与仍缺少的证据已经识别；不强制固定来源数量。
- 知道目标读者读完后应改变什么。
- 知道文章边界：不写什么、不证明什么。

其他模式在目标问题、证据或实践材料、读者需要获得的解释，以及文章边界足够清楚时即可进入 brief。不要为满足观点文清单而虚构作者立场。
