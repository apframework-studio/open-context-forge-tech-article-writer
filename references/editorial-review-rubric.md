# Editorial Review Rubric

进入 `article.md` 前做编辑审查。目标是判断文章是否可供用户审阅，而不是证明已经完美。

## P0 阻塞问题

出现任一项，不进入 `published`：

- 没有明确核心立场。
- 大纲和正文不一致。
- 关键事实没有来源，且被写成确定性判断。
- 图片路径、本机绝对路径或 vault 内部过程文本泄露到正式稿。
- 将过程草稿、临时 brief 或 review note 写入 vault，污染知识库空间。
- 存在 `TODO`、`TBD`、未完成段落。
- 文章只是功能清单，没有论证主线。
- 引用资料和结论之间没有可解释关系。

## P1 需要修复

- 开头太慢，观点出现太晚。
- 章节标题像目录，不像论证步骤。
- 某些段落过长或同时表达多个意思。
- 过度依赖英文术语，但没有解释其意义。
- 缺少边界和局限，读起来像宣传稿。
- 图表存在，但没有帮助论证。
- 结尾只是重复正文，没有上升到方法论或趋势判断。
- 风格重写用力过猛，改掉了原本自然、准确的句子。
- 出现明显解释腔、总结腔、口头禅或面向读者的训人语气。

## P2 可后续优化

- 可以增加一个更锋利的标题。
- 可以补一个对比表或流程图。
- 可以补一段实践验证。
- 可以强化和已有知识库中某个 claim / framework 的连接。
- 可以拆出一篇后续文章。

## 审查清单

| 维度 | 问题 |
|---|---|
| 立场 | 一句话能否说清文章判断？ |
| 反对对象 | 文章是否反对了某个浅层看法？ |
| 来源链 | 事实是否可追溯到 source / wiki / raw？ |
| 结构 | 每一节是否推进论证？ |
| 风格 | 是否符合“技术判断、结构化、深度解释”？ |
| 边界 | 是否说明适用和不适用场景？ |
| 视觉 | 图表是否服务论证？ |
| 发布 | 是否无 TODO、本地路径、内部 metadata？ |

## Review Report

```markdown
## Editorial Review

### Verdict

article-ready | needs-revision | blocked

### P0

- None

### P1

- <issue>

### P2

- <suggestion>

### Final Fixes Applied

- <fix>
```
